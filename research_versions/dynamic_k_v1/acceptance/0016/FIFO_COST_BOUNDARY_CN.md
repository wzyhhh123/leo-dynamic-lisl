# BBM精确FIFO成本观察边界

只读外部CPython栈采样表明，PERSIST/BBM分支在网络/N1a推进至t=6之后，N1b DeliveredAgeLedger.consume仍处理已有服务观察记录。记录区间从[4.075459385480014,4.25198328638308]进展至[4.287682417738391,4.702365797967492]；节点也有变化。它不是已证实的事件时钟停滞。

当前源码runtime/n1b_fifo.py的_interval先构造所有incoming端点形成cuts，再对每个相邻区间扫描全部incoming，逐个进行Fraction比较及clip。若有m个流片段与c个切分区间，这段扫描需要O(mc)次包含判断，c可能随m增加。这是直接源码与栈位置支持的成本机制；本轮没有逐调用profiler统计，不能把它声明为已测得占比或唯一瓶颈，也未读取精确的运行中cohort总数。

多跳改路后流片段增多可能放大成本，但其因果贡献尚未单独实测。不会以缩短H、减少真实流量、删除年龄cohort或放宽精度绕过。本轮不改N1b实现。

栈采样仅读取进程，未注入代码；采样不是完整native checkpoint，也不是完整分支结果。采样工具以下载wheel、独立exe及SHA纳入新修订，没有安装或修改Conda环境。完成的分支墙钟含少量验收外包装和系统负载；外部采样额外开销没有配对测得，因此不宣称零开销。

后续若另获授权，可审计区间扫线/端点索引来避免每个cut重扫incoming；必须保留准确Fraction、同时到达比例混合、本地FIFO排序、全部原始注入年龄、数值闭合误差账本，并对完整服务记录及结果进行精确等价验证。此处只给建议，不实施优化。
