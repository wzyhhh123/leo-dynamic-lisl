BBM最终驻留27个cohort/Stream、479条新增年龄观察、10条closure、7595条非零roundoff审计。最终驻留量不是峰值或累计创建量；观察记录不是传播事件heap pop数；非零审计条数不是全部检查次数。

## 冻结调用链与结构成本

`n4_p0.score_action → AtomicTopologyController.advance_to → DeliveredFluidEvaluator.advance_to → N1a推进/评价 → age.consume → _interval → _order / flight扫描 / cuts / parts / LocalFIFO.advance_piece → Cohort.consume → _check_state`；评价器随后两次metrics，中间记录交付差额审计。consume按cursor单次读取新观察，不是每次重算全部历史FIFO。

| 工作 | 来源与支持的结构结论 | 未测项 |
|---|---|---|
| 每节点flight遍历 | 源码每节点构造list(self.flight.items())并扫描全部key，约节点数×flight-key数 | 原BBM峰值key数、独占时间 |
| cuts排序及incoming覆盖筛选 | c个切段各扫描m个incoming，谓词评估严格为m×c；排序依赖Fraction端点 | 原BBM m、c、p的逐区间分布 |
| 创建/裁剪/部分消费 | 每个有效输入切片、输出、尾段保留都会产生Stream；连续非空输入区间建立Cohort；消费依次处理FIFO头 | 原BBM累计分配、拆分、最大活跃量 |
| original-time组件 | canonical_components按相同仿射表达式规范化并排序，Fraction精确计算 | 峰值组件数、最大中间整数位宽 |
| total/状态闭合 | LocalFIFO.total扫描当前rows；每区间完整Q/I/A/D核对并精确cohort守恒 | 原BBM扫描规模和独占时间 |
| metrics和账本 | 重扫剩余量/原始时刻矩并deepcopy审计列表；6次调用属源码推导 | 原BBM各次账本规模及耗时 |

只讨论操作次数时，覆盖筛选为O(m c)，c至多2m+1，因此存在二次扫描。Fraction每个操作的位复杂度还依赖分子/分母大小，不能将此写成整体实时时间复杂度。已封存最终Fraction见证位宽不是中间峰值，不足以判定“大整数爆炸”。
