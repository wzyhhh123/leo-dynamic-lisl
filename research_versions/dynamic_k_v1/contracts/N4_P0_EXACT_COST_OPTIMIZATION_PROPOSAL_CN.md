# N4-P0 精确成本优化建议 — 未实施

PILOT_ONLY。独立 HOLD 分支的初次实测：净化 6.7296935 s，分支推演/评分 31.3563975 s；后者互斥分类中绑定与 hash 为 26.3740046 s，FIFO 为 1.206448 s，网络为 0.2736349 s，终端能耗为 0.2802299 s，其余为 3.2220787 s。这些数值包含 Python profile 开销，只是该分支的仪器化测量，不外推为全部动作或正式运行速度。完整 epoch 及完整候选成本见 acceptance/0010/one_epoch_cost.json。

本轮不实施优化，不关闭校验、不裁物理宇宙、不增 worker。单分支已超过三秒工程预算，完整预实验授权应先暂缓。优化需要另行授权并做精确等价验收。

## 优先级一：绑定验证与物理摘要的明确只读接缝

当前同一候选推演内多次重新校验相同冻结源码、合同、manifest 与物理 catalog。应先区分原始字节读取/hash、路径/重解析点安全检查、manifest 解析和物理摘要序列化的成本；不要将其笼统称为网络仿真慢。

可审阅的新方案是显式的不可变依赖快照/校验令牌：开始时完整核对所有原始字节和独立锚，预测期间使用已验证且无法被修改的依赖快照，结束时完成规定复核。必要条件包括文件身份与内容不会在评分期间被写入、删除或替换，路径/重解析点不能变更；活跃物理状态、时间及每次动作资源校验仍必须执行。仅缓存 mtime/size，或仅在前后 hash 相同，都不足以排除中途修改后恢复。若不能提供这种可证明的不可变性，继续使用当前完整验证，不以“工程提速”为由关闭它。

该方案需独立版本接口与保护测试，不在冻结生产核中改写 verify。正常输入逐字段等价；篡改、删除、改名、换行、输入替换、父修订变化和评分期间变化都须失败关闭。除耗时/显式校验元数据外，评分、动作、FIFO、服务、能耗和失败原因不得变化。

## 优先级二：完整候选枚举中的纯几何与重复事务工作

保持全供应 catalog 的实际唯一候选数、合法数、拒绝理由及完整释放语义。可以审计同 epoch 重复的纯 SGP4/LOS/FoR 点位检查，缓存键必须包括原始 TLE/硬件/catalog 绑定、精确时间、精确终端对；不做时间量化、插值或放宽窗口。ready 时间随真实 TX/free/setup 变化，不能用当前点结果替代 ready 点。

事务预演若要缓存或复用，键还必须覆盖完整终端/绑定/预约/事件状态、精确释放集合、模式、双端 setup 与时间，且证明预演不突变共享对象。不能把 ADD 与 BBM/MBB 因终端对相同就当成同一个事务。N2 真 submit 仍再次验证并执行。优化后的全部 masks、合法/截断计数、actual release set 与原版完全相同；小域7个只影响评分，不影响全合法枚举。

## 优先级三：历史克隆与证据构造

已核对冻结 `terminal_executor.py`：`clone_for_transaction` 使用结构复制并保留独立历史列表，历史条目本来就按只读约定共享，不应误报为每次递归复制整个日志。具体静态热点是 `snapshot/_log` 每次对全部 320 个 Terminal 调用 `dataclasses.asdict`，在成千候选的多次事务预演中重复发生。本次粗阶段计时尚未独立量出其中单个函数的净耗时，不能把其静态调用结构当作完整实测分项。

下一步可审阅独立的只读快照/预演记录接口，要求产生与原记录逐字段、逐事件完全相同的 320 终端状态和 details；只有经字段白名单证明全为不可变叶值时，才考虑减少递归转换或精确复用未变化端口。任何新增可变字段都须拒绝或退回原方法。不能删除中间状态、减少账本事件、让延迟快照读到后来的状态，或省略拒绝证据。若无法独立接缝实现而必须改写冻结 `_log/snapshot`，先 STOP 提交最小改动方案，不擅自修改内核。

只考虑已完成、不可变的历史记录共享；当前队列/cohort、in-flight、累计账本、预约、事件 agenda 和可变缓存必须分支独立。不能共享会被 Cohort.consume 修改的对象，不能重建空 FIFO，也不能删除真实历史来提速。

若建立只读历史结构，须逐字段验证原观察游标、年龄分布/分数、J/N/A/Q/I/D、终端驻留和完整日志一致，并验证 clone/checkpoint/replay、候选顺序反转和因果双生。不能让共享对象携带未来真 traffic 引用。SGP4 C 对象的内部可变状态不能未经审计跨分支共享；只读输出数组缓存与可变 propagator 是不同方案。
